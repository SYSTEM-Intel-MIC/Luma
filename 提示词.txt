1. 产品愿景

Luma 的核心理念：

> **用户不应该学习如何操作电脑，只需要告诉 Luma 自己想完成什么。**

传统电脑使用方式：

用户
 ↓
寻找软件
 ↓
寻找菜单
 ↓
寻找按钮
 ↓
执行操作
 ↓
检查结果

Luma：

用户
 ↓
告诉 Luma 目标
 ↓
Luma 理解目标
 ↓
Luma 制定计划
 ↓
Luma 选择工具
 ↓
Luma 执行任务
 ↓
Luma 观察结果
 ↓
Luma 验证结果
 ↓
完成任务

例如：

“帮我整理一下桌面。”

“帮我看看电脑为什么这么卡。”

“帮我检查一下网络。”

“找出电脑里所有关于 XXX 的文件。”

“帮我把这个 PDF 总结一下。”

“打开浏览器搜索 XXX。”

“帮我检查 Node.js 有没有安装。”

“把下载文件夹整理一下。”

“帮我处理这个 Excel。”

“打开 VS Code 并检查这个项目的问题。”

Luma 的目标不是让用户“使用 AI”。

而是：

> **让用户把电脑当成一个可以直接交代工作的对象。**

---

2. 核心产品原则

必须遵守以下原则。

2.1 AI First

Luma 的主要交互入口是 AI。

不要把 UI 设计成传统的：

文件管理器
系统管理器
浏览器
AI Chat
工具箱

然后把 AI 当成其中一个功能。

应该反过来：

                 Luma
                   │
              AI Agent
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
      文件       Windows     浏览器
        ↓          ↓          ↓
      Office    Shell       Web
        ↓          ↓          ↓
             Computer Use

AI 是统一入口。

Tools 是 AI 的能力。

---

2.2 用户只描述目标

不要要求用户告诉 AI：

> “先执行 PowerShell 命令 A，再执行 B。”

用户应该只说：

> “帮我检查网络为什么这么慢。”

Agent 自己决定如何完成。

---

2.3 自主执行优先

Luma 默认应该：

> 理解 → 规划 → 执行 → 验证 → 完成。

不要因为每一个小操作都询问用户而破坏 Agent 体验。

但是：

> **自主 ≠ 无限制。**

高风险操作必须请求授权。

---

2.4 用户始终拥有最终控制权

任何任务都应该支持：

- 暂停
- 继续
- 停止
- 查看当前任务
- 查看执行步骤
- 修改任务
- 用户接管
- 权限授权
- 权限拒绝

如果技术允许，还应支持：

> Agent 执行 Computer Use 时，用户可以随时夺回鼠标和键盘控制权。

---

2.5 可解释但不要啰嗦

Agent 应该让用户知道：

> 它正在做什么。

但不能每一步都输出大量技术日志。

例如不要：

Calling tool filesystem.search...
Argument:
path=C:\Users\xxx\Desktop
recursive=true
...

默认应该显示：

正在检查你的桌面文件……

用户如果展开详细信息，再看到：

filesystem.search
路径：Desktop
递归：是
发现：126 个文件

---

2.6 本地优先

Luma 应尽可能：

- 本地运行
- 本地保存配置
- 本地保存历史
- 本地保存 Memory
- 本地执行工具
- 不强制登录
- 不强制云端账户
- 不建立 Luma 云服务依赖

模型 API 可以使用云端。

但：

> Luma 本身不是 SaaS。

---

2.7 开源优先

整个项目使用：

> GPL-3.0

必须考虑第三方依赖许可证兼容性。

不得随意复制闭源项目源码。

不得把无法兼容 GPL 的代码直接复制进项目。

第三方库必须记录：

package
version
license
source

6. Agent Runtime

这是整个项目最核心的模块。

不要把 Agent 实现成：

LLM → Tool → LLM → Tool

必须实现真正的 Agent Loop。

基本流程：

User Request
    ↓
Context Assembly
    ↓
Model
    ↓
Intent Understanding
    ↓
Planning
    ↓
Tool Selection
    ↓
Risk Evaluation
    ↓
Permission Check
    ↓
Tool Execution
    ↓
Observation
    ↓
Verification
    ↓
Replanning
    ↓
Continue
    ↓
Task Complete

伪代码：

while taskNotFinished:

    observeCurrentState()

    understandUserGoal()

    if informationIsMissing:
        askUser()

    planNextAction()

    selectTool()

    evaluateRisk()

    if permissionRequired:
        requestPermission()

    executeTool()

    observeResult()

    verifyResult()

    if executionFailed:
        attemptRecovery()

    if recoveryFailed:
        askUser()

    if taskCompleted:
        summarize()

必须避免无限循环。

需要：

- 最大 Agent Steps
- 最大执行时间
- Tool Timeout
- Retry Limit
- Token Budget
- 循环检测
- 重复 Action 检测

12. 文件操作安全

例如：

移动 1 个文件
→ Low

移动 20 个文件
→ Medium

删除 1 个普通文件
→ Medium

永久删除 100 个文件
→ High

删除系统文件
→ Critical

禁止 Agent 在没有必要的情况下操作：

C:\Program Files

38. 权限原则

NONE

纯读取信息。

自动执行。

LOW

低风险操作。

自动执行。

MEDIUM

可能修改用户数据。

默认询问。

HIGH

高风险操作。

必须询问。

CRITICAL

严重影响系统/安全的操作。

默认禁止。

必要情况下要求人工明确操作。

65. Agent System Prompt

建立独立的 Agent System Prompt。

核心要求：

You are Luma, a local-first Windows AI agent.

Your job is to help the user accomplish real tasks on their computer.

You should:
- understand the user's goal;
- plan before acting;
- use available tools;
- verify important actions;
- ask for clarification when necessary;
- request permission for risky actions;
- never claim an action succeeded unless verified;
- never fabricate tool results;
- respect user control;
- minimize unnecessary actions;

永久允许

权限记录：

tool
action
scope
createdAt

不要让：
